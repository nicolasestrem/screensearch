## Highlights

### Memory reports, date selection and Telegram digests ([#123](https://github.com/nicolasestrem/screensearch-v2c/pull/123))

Turn captured activity into Markdown notes you can browse in Obsidian, with an optional Telegram digest.

- Pick a single date or an inclusive date range for a manual report, including today (a frozen cutoff, clearly marked PARTIAL). The previous-day shortcut and the daily schedule remain.
- Default-off daily schedule with an explicit time zone, DST handling and a seven-day restart catch-up. Reports are owned files in your chosen folder; your edits are preserved.
- Optional Telegram digests: bot token kept in Windows Credential Manager, per-chunk delivery receipts, bounded retries, and an explicit review step when delivery is uncertain. Empty windows (NO_DATA) never send a message.
- Empty model output after real captured evidence is reported as a failed generation instead of a blank "successful" note.

### Opt-in network API ([#122](https://github.com/nicolasestrem/screensearch-v2c/pull/122))

- The local HTTP API stays **off by default** and keeps bearer-token authentication.
- The bind address is now configurable (IPv4 or IPv6). It defaults to `127.0.0.1`, **including existing installs that already enabled the API**, so upgrading never widens access. Choosing a non-loopback address makes your history reachable over plain HTTP by authenticated devices; the Settings panel explains the risk.
- Hardened listener: Windows exclusive socket ownership, a 64-connection cap and a 30-second request-header deadline. The MCP wrapper and the inference sidecar remain loopback-only.

## Before you update

- **One-way database upgrade (schema 11 → 12).** The first launch of v0.4.1 migrates your database. There is no downgrade, so back up your ScreenSearch data folder first if you may want to return to v0.4.0.
- Updates are delivered automatically to v0.3.2+ installs: the app downloads in the background, verifies the signature, and installs only when you choose to restart.
- The installer is not Authenticode-signed, so SmartScreen may warn on a manual download (More info, then Run anyway). The updater's minisign signature is separate and verifies every automatic update.
- Known: a CodeQL alert on the Windows Credential Manager read path is reviewed as a false positive and awaits maintainer dismissal.

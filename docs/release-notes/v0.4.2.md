## Highlights

### Weekly synthesis, weekly notes and project-note promotion ([#137](https://github.com/nicolasestrem/screensearch/pull/137), [#138](https://github.com/nicolasestrem/screensearch/pull/138), [#139](https://github.com/nicolasestrem/screensearch/pull/139), [#140](https://github.com/nicolasestrem/screensearch/pull/140), [#141](https://github.com/nicolasestrem/screensearch/pull/141))

Turn a week of saved daily reports into cross-day memory, and keep the parts you care about in one project note.

- A weekly synthesis covers one complete ISO week and is built from that week's saved daily reports, never a fresh scan of raw captures. Statuses stay truthful: NO_DATA (including a fully covered week whose dailies are all NO_DATA), PARTIAL with the missing dates named, OK only with complete daily coverage, BLOCKED when the answer model is missing, FAILED on errors.
- Weekly notes are written to `ScreenSearch/Weekly/YYYY-Www.md` and listed in `ScreenSearch/Index.md` with links to the daily notes they consumed. NO_DATA, blocked and failed weeks write no note; an edited weekly note is preserved and reported as a conflict.
- Default-off weekly schedule with its own time and time zone. **Run most recent complete week** works while the schedule is off. After a restart the app catches up the four most recent due weeks, oldest first; older or failed scheduled weeks are listed as missed, never reported as covered.
- Promote selected decisions, open questions, next steps or activity from a saved daily or weekly report into one project note you create under `ScreenSearch/Projects/`. Nothing is written until you confirm the preview; each promotion appends a dated block with its provenance and never rewrites existing lines.
- Optional weekly Telegram digest under its own consent, off by default. The daily consent never authorizes weekly sends. The digest is built from the saved synthesis; no second model runs.

### Memory API for external agents ([#126](https://github.com/nicolasestrem/screensearch/pull/126), [#127](https://github.com/nicolasestrem/screensearch/pull/127), [#128](https://github.com/nicolasestrem/screensearch/pull/128), [#129](https://github.com/nicolasestrem/screensearch/pull/129), [#130](https://github.com/nicolasestrem/screensearch/pull/130))

The opt-in HTTP API (still off by default and loopback by default) gains read surfaces for agents that keep their own memory of your history.

- `GET /v1/frames` pages through a UTC time window in capture order with full raw and filtered text. `GET /v1/coverage` reports stored counts, retention policy and capture observations, and states unknowns explicitly instead of treating gaps as inactivity.
- `GET /v1/reports` and `GET /v1/reports/{run_id}` return already saved daily and weekly reports, each labeled with its `kind`. Reads never generate, retry, schedule or deliver a report.
- An independent read-only token (Settings → HTTP API) can read history but is refused with 403 for creating or resolving marks, capture requests and Ask. Upgrades start with no read token, and the existing token keeps its permissions.
- The bundled `screensearch-mcp.exe` adds `list_frames`, `get_capture_coverage`, `list_reports` and `get_report` (13 tools; 10 with `--read-only`, which filters tools but is not authorization). It can target an explicitly configured remote HTTP or HTTPS API root with `--api-url` or `SCREENSEARCH_API_URL`; it ignores proxy settings, refuses redirects and keeps certificate verification. The app's own listener still serves plain HTTP.

### Security and dependency updates ([#120](https://github.com/nicolasestrem/screensearch/pull/120), [#121](https://github.com/nicolasestrem/screensearch/pull/121), [#125](https://github.com/nicolasestrem/screensearch/pull/125))

- rustls 0.23.45 and rustls-webpki 0.103.15; patched UI build dependencies (brace-expansion, postcss-selector-parser, source-map-js).
- API status diagnostics now redact tokens.
- The CodeQL alert on the Windows Credential Manager read path, listed as known in v0.4.1, has been dismissed as a reviewed false positive.

## Before you update

- **One-way database upgrade (schema 12 → 13).** The first launch of v0.4.2 migrates your database. There is no downgrade, so back up your ScreenSearch data folder first if you may want to return to v0.4.1.
- Note frontmatter now accepts only schema 1 (daily and selected-date notes) or 2 (weekly notes). Any other schema number, for example from a hand-edited note or a future build, is rejected as a file conflict (`FILE_CONFLICT`) instead of being accepted.
- The weekly schedule and the weekly Telegram digest are both off by default. Updating does not schedule, generate or send anything new.
- Updates are delivered automatically to v0.3.2+ installs: the app downloads in the background, verifies the signature, and installs only when you choose to restart.
- The installer is not Authenticode-signed, so SmartScreen may warn on a manual download (More info, then Run anyway). The updater's minisign signature is separate and verifies every automatic update.
- The MCP wrapper ships only inside the Windows installer. Standalone macOS and Linux wrapper archives are not published with this release; build the wrapper from source with `cargo build --locked -p mcp --release` (see `docs/MCP.md`).
- Known: the weekly features and promotion have passed automated tests and the Windows CI and native test chain, but not yet a native interactive acceptance run (a real week in the installed app, Obsidian inspection, a promotion, a live weekly Telegram send). The new read-token controls in Settings have likewise not had a native interactive run.

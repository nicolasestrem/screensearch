On 2026-11-02 the store stopped carrying a migration chain. schema.rs now holds the whole v14 DDL, 29 tables including the eleven work-graph tables, and schema_version is written once when the file is created.1 The forward-only steps for 0.2.x through 0.4.2 were removed from the code and kept only as historical notes in the spec.2

The cutover was a copy, not a migration: ssv2c-rebuild read the old database read-only and wrote a fresh v14 file, leaving screensearch.db.v13.bak beside it.3 212 sessions and 41,208 frames came across, and the only write failure was one frame with a NULL window title. Nothing tolerates a retired settings key any more: the file is rewritten once with that key removed.

ScreenSearch 0.4.5 · P2 direction checkpoint

Three design directions, same content, same five screens

Each direction is one self-contained HTML file with its CSS inline, system fonts only, no network request. Each renders the same five screens: Settings, search results, a session card, an Ask answer with citations, and a gallery of every control state. Pick one, or name a merge, and the choice is written into specs/UI_REFERENCE.md section 1 before any screen work starts (0.4.5 D4, D5).

To view one full screen:

  1. Run this in the repository root: start docs\kickoffs\P2-directions\direction-a.html (replace a with b or c).
  2. Or click Open full size under any frame below.
  3. Each file has its own theme button at the top. Every direction ships both themes except where noted.

The frames below are the real files, scaled to about 33 percent so all three fit side by side. Scrolling inside a frame works; colours and type read better in the full screen view.

A Command Deck, refined

The v1 console kept and refined: warm graphite, one signal orange, hairline discipline. Nothing is a new language, the change is craft: type scale, density, light theme. Familiar in a minute, precise by the end of a week.

Structure
  • The accent is a state channel, not paint: a 2px bar plus a surface shift marks selection, focus and the primary action, and nothing else.
  • Recall carries a CSS-drawn density strip: 48 half-hour ticks, a selection brush, a mono axis. The only data visual in the direction.
  • Autosave is the model: no Save control, per-field Saved flags, a 12 second undo toast, inline destructive confirm.

B Paper Ledger

Your screen history as a working paper: a light-led reading surface, printed tables, no dashboard. One serif voice for titles and evidence, a sans for machinery, one ink blue accent. Everything is a document: hairline rules, aligned figures, margin notes.

Structure
  • A sheet with marginalia: every screen is a document with a narrow right margin carrying the facts, not a dashboard with cards.
  • Footnote apparatus on the Ask screen: real superscript numbers and a matching notes block; links are underlined, actions are text with a rule beneath.
  • The form gallery is a labelled state table with n/a where a state cannot exist, instead of faking it.

C Signal Console

An instrument panel for your own screen history: dense, chronological, logbook first. Structure carries the signal: hairline panels, tabular figures, a context rail on every screen. Cyan marks action, violet marks only relationships, monospace does the measuring.

Structure
  • The gap is the divider: nav, pane and context rail separated by 1px grid gaps in the hairline colour, so surfaces do the work instead of borders.
  • Two accents with a hard boundary: cyan is action, selection, focus and match; violet appears only on entity chips, thread membership and relationship spines.
  • Data as data: the Ask screen shows the retrieval path as threads / sessions / frames / tokens, the session card carries a metrics band, the gallery is a 13 by 6 state matrix.

All three files are self-contained: one style block, system fonts, no network request, no build step. Contrast pairs and their ratios are recorded in a comment at the top of each file. Each direction's whole token system is a commented custom property block at the start of its style block, which is what P2 turns into the three layer token file after the pick.

Nothing below happened yet: no token file, no Tailwind config, no primitive component, no app route. Those are the real P2, and they wait for the pick (0.4.5 D4).

One structure, two skins, against the original

The maintainer kept Signal Console's content, density, logbook chronology, context rail and tabular figures, and rejected its skin. D and D2 keep that structure exactly and differ from each other only in accent and neutral family. C stays here as the reference. Each file is one self-contained page with inline CSS, system fonts only and no network request, rendering the same five screens: Settings, search results, a session card, an Ask answer with citations, and every control state.

To view one full screen:

  1. Run this in the repository root: start docs\kickoffs\P2-directions\direction-d.html (replace d with d2 or c).
  2. Or click Open full size under any frame below.
  3. Each file has its own theme button at the top right; D and D2 open in light, C in dark.

The frames below are the real files, scaled to about 33 percent so all three fit side by side. Scrolling inside a frame works; colours and type read better in the full screen view. The decision itself is written up in PICK.md next to this file.

C Signal Console

An instrument panel for your own screen history: dense, chronological, logbook first. Structure carries the signal: hairline panels, tabular figures, a context rail on every screen. Cyan marks action, violet marks only relationships, monospace does the measuring.

Structure
  • The gap is the divider: nav, pane and context rail separated by 1px grid gaps in the hairline colour, so surfaces do the work instead of borders.
  • Two accents with a hard boundary: cyan is action, selection, focus and match; violet appears only on entity chips, thread membership and relationship spines.
  • Data as data: the Ask screen shows the retrieval path as threads / sessions / frames / tokens, the session card carries a metrics band, the gallery is a 13 by 6 state matrix.

D Logbook, ink skin

Signal Console's structure and density, kept exactly, in a calm grown-up skin. Cool slate neutrals and one ink-blue accent; red, amber and green only as states. Density from alignment and rhythm: nothing below 12px, mono only for measured values.

Skin
  • One accent, ink blue (hue 258), marks action, selection, focus and the matched term; matches are an accent wash with an accent underline, no yellow.
  • Neutrals are one cool slate family (hue 252, low chroma) per theme: not warm graphite, not paper beige.
  • Success, warning and danger stay green, amber and red, used only as states, never as decoration.

D2 Logbook, pine skin

The same file as D, byte for byte outside the token block and the skin labels. Near-neutral graphite and one pine-green accent; success folds into the accent. Fewer hues on screen than D: pine, then red and amber only as states.

All three files are self-contained: one style block, system fonts, no network request, no build step. Each file's whole token system is a commented custom property block at the start of its style block, which is what P2 turns into the three layer token file after the pick. Contrast for D and D2 was measured on the rendered pages in both themes; the worst ratios are in specs/05_BUILD_REVIEW.md.

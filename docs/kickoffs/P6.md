## Contracts you must satisfy

- **Session vectors match text embeddings** (`§4`, `§7i.2` stage 2). `session_vectors` is the vec0
  table with `FLOAT[768] distance_metric=cosine`, the same model and dimension as text embeddings.
  The embedded text is the concatenation of the session's non-NULL `title` and `summary`. A session
  with both NULL gets no row and is never embedded as an empty string. Upsert by `session_id`.
  When a session is deleted, its `session_vectors` row is deleted in the same transaction: a vec0
  table carries no foreign key, and a DDL trigger would be a schema change (P3 owns the DDL), so the
  deletion belongs in the store's session-delete path, with a test.
- **One new job kind, `session_embed`** (`§7i.2`, 0.4.5 D11). It lives in its own kernel module,
  backfills in bounded batches (most recently updated sessions first, since no content hash exists
  for sessions and the vec0 row has no timestamp; replay is idempotent through the upsert), runs on
  demand and on idle under the existing scheduler and pressure throttle, and never touches the
  capture hot path. Append its variant, string mapping and dispatch arm to the three registry sites
  P5 edited: after P5's scaffolding, one variant and one arm, never a rename or a reorder.
- **The planner produces two things** (`§7i.1`). A time intent ("last week", "before the release",
  "this morning", "yesterday") resolves to a half-open `[window_start, window_end)` in unix ms; with
  no time intent the window is unbounded and **both `ask_turns` columns stay NULL** (NULL means the
  whole history; the planner never fabricates bounds). An entity mention resolves against
  `entities.canonical_name` and `entity_aliases.alias`; with no graph row or no match the mention
  falls back to plain text matching, so a database whose graph tables are empty still answers.
  Both results are recorded on the turn.
- **Retrieval stages run in the fixed order of `§7i.2`**, and a later stage only narrows an earlier
  one's candidate set.
  1. Threads: threads whose `[first_seen_at, last_seen_at]` overlaps the planned window, or that
     contain an entity-resolved session.
  2. Sessions: hybrid retrieval over the candidate sessions, FTS on session `title`/`summary`
     combined with `session_vectors` cosine similarity.
  3. Frames: the existing hybrid frame search, restricted to frames inside the winning sessions.
  4. Assembly: context packed to the existing token budget, best evidence first; truncation drops
     the tail, never the citations of what remains.
  Record each stage's candidate count and the assembled token total per turn as `stage_counts` and
  `tokens_assembled` on the same terminal event that carries the citations, and log them. The
  `ask_turns` DDL has no column for either value and adding one is a P3 schema change: if the
  maintainer requires them persisted in the table, stop and amend `03 §4` first. The P4 harness
  passes the terminal payload through verbatim into `runs.jsonl`, so these numbers are readable
  without touching its crate.
- **The non-blocking fallback is mandatory** (`§7i.1`, last sentence). With empty graph tables the
  thread stage returns nothing, so the session stage takes every session overlapping the window.
  When no session wins (no summaries, no vectors), the frame stage runs the existing hybrid search
  over the window directly. Consequence, stated as the contract: on a database with an empty graph
  and no session summaries, Ask v2 behaves exactly like today's frame-level Ask with an optional
  time filter, and is therefore never worse than the P4 baseline. A test with empty graph tables
  must prove this path.
- **Citations** (`§7i.3`). Every answer cites both kinds of evidence. The cited sessions are the
  distinct non-NULL `frames.session_id` values of the frames actually included in the assembled
  context, ascending; the cited frames are those included frame ids. That definition makes "every
  cited frame belongs to a cited session" true by construction, and it keeps citations provenance
  derived rather than parsed from prose (the `crates/inference/src/answer.rs` rule).
- **The SSE stream is extended, never replaced** (`§7i.3`, 0.4.5 D12). `thinking`, `token`,
  `citation` (with `frame_id`), `done` and `error` keep their names and meanings exactly. Add
  exactly one new terminal event, emitted once before `done`:
  `{"type":"citations","sessions":[id...],"frames":[id...],"thread_id":id,"turn_id":id,"stage_counts":{"threads":n,"sessions":n,"frames":n},"tokens_assembled":n}`,
  carrying the arrays and diagnostics described above. Unknown event types are ignored by the
  existing MCP aggregator (`crates/mcp/src/sse.rs`, the catch-all arm), so a client that does not
  know the event renders today's answer unchanged; a test asserts that. `docs/API.md` is updated in
  this phase for the new event, the new request field and the turn record. P8 extends the same
  document in Wave C with the new read routes (`/v1/threads`, `/v1/entities`, `/v1/insights`); your
  change is additive to it and must not fence it off.
- **Multi-turn persists conversations** (`§7i.4`). A question without a thread id creates an
  `ask_threads` row (its `title` stays NULL; naming threads is P9's job) and turn `ordinal` 1; a
  question with a thread id appends the next ordinal. Each turn stores the question, the answer
  (NULL while streaming and on failure), the resolved window and `resolved_entities` as a JSON
  array of entity ids. A follow-up reuses the previous turn's window and entities unless the new
  question overrides them. `UNIQUE(thread_id, ordinal)`; deleting a conversation cascades to its
  turns and touches no frame, session, graph row or insight.
- **Nothing runs on the capture hot path** (0.4.5 D11). Session embedding, planning and retrieval
  are request- or idle-driven only, under the existing scheduler and pressure throttle (`03 §5`).
- **Additive persistence only.** Add `crates/store/src/ask.rs` and the retrieval methods the
  pipeline needs; new `Store` methods carry a default body (the `history_readiness` precedent in
  `crates/traits/src/contracts.rs`) so no existing implementation or fake breaks; never change an
  existing method's signature or behaviour. Existing frame search keeps its exact semantics: the
  session-restricted variant is a new method, not a parameter change on an existing one. The kernel
  already holds `Arc<dyn Store>` and reaches providers through `traits` (reuse the embedder it
  already holds for `embed_text` jobs and the answer provider it already exposes): add no new
  dependency to `crates/kernel`.
- **The inference ask path keeps its shape.** Retrieval and assembly stay outside it; it receives
  the assembled chunks (now carrying their session id and a short session label) and the token
  budget it already respects. The prompt may name sessions, but citations remain the provenance of
  what was placed in the prompt. Vision and summary paths are untouched.
- **`AnswerDelta` is a `ts-rs` export.** Regenerate the bindings in the same commit and commit only
  the files your change produces; `git diff --exit-code -- ui/src/bindings` must be clean afterward.
- **`crates/mcp` and `crates/api` read surfaces are not yours.** The MCP tools that expose sessions
  and the new read routes are P8. Do not extend a tool, and do not add a route beyond the ask
  handler the planner needs.

```
**Acceptance:** on the P4 automatic set, recall@10 and known-fact answer rate beat the baseline by the
margins frozen at Gate A; citation validity 100%; p95 latency within the budget frozen at Gate A;
full suite green.
```

Decomposed:

- [ ] The P4 harness runs unchanged against the built app on the same seed and reports evidence
      recall@10 and the known-fact rate above the Gate A thresholds, per generator, with the report
      pasted verbatim into `specs/05_BUILD_REVIEW.md`. The database grows between runs, so the pair
      sets are not identical: the comparison is between aggregates computed by the same rule over
      the same five generators, and the per-generator table is the comparison surface.

      belongs to a cited session; every cited session exists and overlaps the window. Any invalid id

      can be attributed to a stage.
- [ ] `cargo test --workspace` is green, including a test that the stream still emits every existing

      follow-up turn reuses the previous window and entities.

  harness.

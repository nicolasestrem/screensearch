## Contracts you must satisfy

**Screen list**

- Rebuild on v2, without changing behaviour: Deck, Search/Recall, Timeline, Session, Moment, Flow
  overlay, the Reports and Memory panels, and the Promotion dialog (`docs/0.4.5.md` P10).
- Deck: capture status, today's activity, the Jump-back card with session framing, the Intentions
  strip (`UI_REFERENCE §4`, Deck row). One primary action.
- Recall: search and reports on their existing contracts, including the content-vs-chrome toggle,
  the report download naming and the report footer line (`UI_REFERENCE §4`, Recall rows;
  `03 §8b`). The reports panel keeps its typed controls and its states.
- Timeline: the Scanline Timeline or its v2 successor, whichever `UI_REFERENCE §1` names
  (0.4.5 D4). It must encode real capture density, not decoration (`UI_REFERENCE §1`, §10.7).
  If the pick names a successor, its fixed band reservation replaces the four-lane rule; `§8`
  already allows "the equivalent fixed reservation of its v2 successor", so document what the
  reservation is in the PR and do not edit the spec.
- Session: title, span, tool/host chips, frames strip, exchanges, Recap; open sessions say so;
  low confidence is surfaced honestly; one scroll context (`UI_REFERENCE §4`, Session row).
- Moment: image, recognized text and raw text that grow inline with their content, vision tags,
  context, actions, the "part of session" line when a session exists (`UI_REFERENCE §4`, Moment
  row). The recognized-text block keeps its scoped horizontal scroll exemption; everything else
  wraps (`UI_REFERENCE §8`).
- Flow overlay: frameless, always-on-top, hidden-not-destroyed, input focused on show, arrow
  navigation, Enter opens the Moment in the main window, Escape and blur dismiss, Tab or a `?`
  prefix switches to Ask, an empty query shows the where-was-i strip (`UI_REFERENCE §3`). It must
  read as ScreenSearch, not as a generic launcher.
- Promotion dialog: keep its confirm flow and copy contract while restyling (`UI_REFERENCE §11`,
  `03 §8e`).
- No new route, no new NavRail entry, no change to the shell (`UI_REFERENCE §3`).

**Shim and legacy tokens**

- Delete `ui/src/styles/tokens.compat.css` and its `@import` line, then delete every legacy token
  definition that only the shim kept alive. The v1 names to end with zero hits across `ui/src`
  include `--bg-base`, `--bg-surface`, `--bg-overlay`, `--line`, `--ink`, `--ink-muted`,
  `--ink-faint`, `--accent`, `--accent-wash`, `--scrim`, `--glow-scan`, `--danger`, `--warn`,
  `--ok`, `--font-display`, `--font-body`, `--font-mono`, `--radius-panel`, `--radius-chip`,
  `--radius-ribbon`. If a v2 semantic token does not cover one of them, that is a stop, not a
  reason to keep the old name.
- Extend the P2 token lint rule in `ui/eslint.config.js` to all of `ui/src`. It must fail on raw
  hex, px font sizes and non-token spacing outside the token files themselves. Do not weaken the
  rule while widening it: a rule that only catches primitives has not been extended.
- Delete dead components left behind by the redesign, in `ui/src/components/domain` and, when it
  has no importers left, `ui/src/components/icons.tsx` (P2 replaced the icon set). Prove each
  deletion with a grep that shows no importer, and keep every component that P7, P9 or a route
  still imports.
- One primitives-path deletion is yours: P2 kept `Expander` in `ui/src/components/primitives` as a
  v2-token adapter "until P7 replaces that screen", P7 has replaced it, and nothing else imports

**Layout and performance**

- One scroll context per route; fixed rails; no nested scrollable regions; no horizontal
  scrollbar at any supported size, 1280×720 through ultrawide, at 100 / 125 / 150 % DPI
  (`UI_REFERENCE §8`).
- No cumulative layout shift on data arrival: skeletons reserve final geometry, status chips have
  stable widths, toasts and banners overlay rather than push (`UI_REFERENCE §8`).
- Re-measure and paste the `UI_REFERENCE §8` budgets: initial JS ≤ 250 KB gzip, route-split per
  page, virtualized frame grids and timeline, lazy `FrameImage` with async decode, results
  rendered < 100 ms after data, interaction latency < 100 ms, no layout shift. The budgets are
  unchanged by v2; a direction that cannot meet them is a regression, not a renegotiation.
- The overlay keeps its own budgets: visible < 150 ms from hotkey when warm, first results within
  the < 200 ms search budget (`UI_REFERENCE §3`).

**Privacy and accessibility**

  session bands, `prefers-reduced-motion` honoured for every animation the refont adds (`UI_REFERENCE`
  §7). No new ambient motion that ignores it.

**Code rules**

- Tokens only, P2 primitives only; no new primitive and no new token (`UI_REFERENCE §2`).
- Typed IPC only, `ui/src/bindings` never hand-edited (`UI_REFERENCE §6`).

## Verification, in order

Run the UI first: the Rust build embeds `ui/dist`, so a stale or broken UI bundle invalidates the
Rust steps. One command per line, no `&&`:

```
cd ui
npm ci
npm run lint
npm run build
cd ..
node scripts/stage-mcp.mjs
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo build --workspace
cargo test --workspace
git diff --exit-code -- ui/src/bindings
```

Then the P10-specific checks:

```
test ! -f ui/src/styles/tokens.compat.css
grep -rn 'tokens.compat' ui/src ui/index.html
grep -rnE -- '--(bg-base|bg-surface|line|ink|ink-muted|ink-faint|accent|accent-wash|scrim|glow-scan|danger|warn|ok|font-display|font-body|font-mono)\b' ui/src
grep -rn 'ConnectionsPanel\|EntityChips' ui/src
cargo test -p capture privacy
grep -rn 'ScanlineTimeline\|Scanline' ui/src | wc -l
```

What each proves: the shim is gone and nothing imports it; no legacy token name survives anywhere
in `ui/src`; P9's components are referenced by the routes that place them; the capture privacy
gate tests still pass, which is the self-exclude gate the overlay depends on; the last line is the
count of timeline-signature references, which you report against the `§1` pick (it is information,
not a pass condition).

Paste the raw output of every command into `specs/05_BUILD_REVIEW.md`, and the phase record into
`specs/06_PATCH_PLAN.md`, `specs/07_KNOWN_GAPS.md`, `specs/08_CHANGELOG_AI.md` and `CHANGELOG.md`
(`04` §7).

## Stop conditions

Stop and ask, and record the item where indicated, when:

- a product decision is needed that the specs do not answer: log it in `specs/07_KNOWN_GAPS.md`;
- the specs contradict each other: log it in `specs/06_PATCH_PLAN.md`;
- the work needs a file outside the owned paths, including `ui/src/components/shell`,
  `ui/src/app`, `ui/src/components/intelligence` or `crates/`;
- a schema change outside P3 is needed (0.4.5 D2, `03 §4`);
- any verification command stays red after a genuine fix attempt (`04` §6).

P10-specific:

- A legacy token has no semantic equivalent in `UI_REFERENCE §2`, so deleting it would change what
  a surface means. Adding a token is a P2 contract change; record it and stop.
- A `components/domain` component is still imported after the refont and has no v2 form. Deleting
  it would break a screen; keeping it half-converted is the dead weight this phase exists to
  remove.
- A budget cannot be met after a genuine optimization attempt. `UI_REFERENCE §8` forbids
  renegotiating it; record the measurement and stop.
- `ConnectionsPanel` or `EntityChips` cannot express what Session or Moment needs. Do not fork
  them; P9 owns them and has merged.
- The refont of the timeline would change the fixed band reservation in a way `§8` does not
  already allow.
- The overlay work runs into a platform behaviour you cannot address in app code. The 0.3.2
  precedent applies (`04` §3): stop on that item, record the best mitigation in
  `specs/07_KNOWN_GAPS.md`, and continue the rest of the phase.
- A new route, a new nav entry or a new setting appears to be needed. None of the three is in this
  phase's contract.

## Do not

- No stubs, no placeholder screens, no mock data, no "Coming Soon" (`04` §4, `UI_REFERENCE` §10.1).
- No hardcoded expected values in tests.
- No weakening of a lint rule, an eslint config or a test to get green, including while widening
  the token rule's scope.
- No renegotiated performance budget and no "measure later".
- No deleted component that still has an importer; no kept component that nothing imports.
- No change to the shell, the nav, the route table, P9's components or P2's primitives.
- No commits to `main`, no push, no merge, and no commit or push at all until the maintainer
  validates the content and names the target repo `nicolasestrem/screensearch` (0.4.5 D18).

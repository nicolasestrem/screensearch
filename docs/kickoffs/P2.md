# P2: Design system v2 (UI foundation)

Wave A of the 0.4.5 arc, and it feeds Gate A and the release tag **`v0.4.3`**. It ships no screen: the tokens, primitives, icons and compatibility shim land here so P7 (shell and Settings v2) and P10 (the refont) have something to build on. This file is the whole instruction for the phase. You do not need the roadmap.

## Contracts you must satisfy

### The two hard fences

- **Fence 1, token discipline.** Inside `ui/src/components/primitives` a component references **semantic and component tokens only**, never a primitive token directly (`UI_REFERENCE` §2). No raw hex, no `rgb()`/`hsl()` literal, no px font size, no magic spacing value, no hand-written colour mix (`UI_REFERENCE` §2; `04` §4 UI guardrails). The rule is machine-enforced, not reviewed by eye: the enforcement must fail on a violation (P2 acceptance; see Verification).
- **Fence 2, the direction is frozen.** The direction recorded in `UI_REFERENCE` §1 is the brief. Implement it; do not explore alternatives, do not re-pick a palette, a type pairing or a radius scale mid-build, do not "improve" it toward your own taste (0.4.5 D4). If the recorded direction cannot be implemented as written, stop (Stop conditions), never substitute.

### The seven deliverables, in the roadmap's order

1. **Direction checkpoint (precondition, not work on this branch).** Already described under Branch. On this branch `/kitchen` renders the **picked** direction on the same content the checkpoint used: a real Settings page, a search result list, a session card, an answer with citations, and a form showing every control state, plus a complete primitive gallery. Themes: whatever `UI_REFERENCE` §1 records (one or two), switchable inside the route. `/kitchen` must be dev-only: gate it on `import.meta.env.DEV` exactly as `ui/src/components/shell/AppShell.tsx` gates `DevStateBadge`, so the route and its code tree-shake out of the production bundle.
2. **Token architecture, three layers, in `ui/src/styles/tokens.css`** (`UI_REFERENCE` §2): *primitive* (raw scales: colour ramps, type scale, space scale, radii, shadows, durations) → *semantic* (`--surface-raised`, `--text-secondary`, `--border-subtle`, `--action-primary-bg`, `--focus-ring`, and the rest of the set you need) → *component* (only where a component needs its own knob). Themes are semantic-layer swaps under `[data-theme]`; a new theme never touches a component. The Tailwind theme in `ui/tailwind.config.js` maps onto the same custom properties, so a Tailwind utility and a hand-written `var(--...)` resolve to one value. Z-layers stay base / rail / overlay / toast. Global resets and base element styles stay in `ui/src/styles/globals.css`, which already imports `./tokens.css`; add `@import "./tokens.compat.css";` directly after that import, so both entrypoints (`ui/src/main.tsx` and `ui/src/overlay-main.tsx`) receive the shim and no `ui/index.html` edit is needed.
3. **Typography** (`UI_REFERENCE` §1; 0.4.5 D15): one text family and one mono family, both OFL-licensed **variable** fonts, shipped as local files under `ui/src/styles/fonts/` with each licence text beside them, declared with `@font-face` in `tokens.css` using weight ranges. Display treatment comes from weight and size, never from a third face. Nothing is fetched at runtime: no Google Fonts, no CDN, no `@import url(http...)`. The built bundle must contain the font files.
4. **Spacing and layout** (`UI_REFERENCE` §2 and §8): a 4-based space scale with named steps, a single density token (`comfortable` / `compact`, `comfortable` the default) that drives row height, control height and grid gap so no screen hardcodes any of them, container widths, and a 12-column content grid for wide screens that collapses to one column below the wide breakpoint instead of scrolling sideways. Every grid item carries `min-w-0` (§8: the Moment `<pre>` horizontal-scroll exemption depends on it, and so does the no-horizontal-scrollbar rule).
5. **Primitives rebuilt from zero** in `ui/src/components/primitives/`. The set is fixed, copy it exactly:

   Button (primary / secondary / ghost / danger × sm / md, icon and loading states), IconButton, Field, TextInput, Textarea, Select, Combobox, Toggle, Checkbox, Radio group, Segmented control, Slider with numeric input, Chip/Tag, Badge, Tooltip, Popover, Dialog, Sheet, Toast, Tabs, Panel/Card, List row, Table, Skeleton, EmptyState, ErrorState, Kbd, Divider.

   Every primitive ships all interaction states (default, hover, active/pressed, focus-visible, disabled, plus its own: checked, selected, open, expanded, invalid, loading), full keyboard behaviour, a visible focus ring, reduced-motion handling, and WCAG-AA contrast in every theme the pick ships (`UI_REFERENCE` §5, §7). Data-bearing primitives (Table, List row, and the screen samples) must be able to show all five view states from `UI_REFERENCE` §4: loading, empty, error, partial, populated.

   **The barrel `ui/src/components/primitives/index.ts` is a compatibility seam, not a fresh start.** `ui/src/components/domain/**`, `ui/src/components/shell/**` and `ui/src/overlay/**` import primitives from it and you may not edit them, so every export name they use today must keep working on v2 tokens. That includes `Expander`, which the new set does not list and which `ui/src/routes/Settings.tsx` still uses: it stays in the barrel as a v2-token adapter until P7 replaces that screen.
6. **Icons** (`UI_REFERENCE` §1): one consistent local SVG icon set at a single stroke width, living with the primitives (`ui/src/components/primitives/`), replacing `ui/src/components/icons.tsx` as the source of truth for everything you own. It is a set of local SVG files, not a runtime icon package and not a network service; if you vendor glyphs from an icon library, keep that library's licence beside the files. `ui/src/components/icons.tsx` itself is **not yours** (Stop conditions): unconverted screens still import from it and P10 deletes it once the last of them stops.
7. **Compat shim** (`ui/src/styles/tokens.compat.css`): alias every v1 token name that unconverted screens still reference (`--bg-base`, `--bg-surface`, `--bg-overlay`, `--line`, `--ink`, `--ink-muted`, `--ink-faint`, `--accent`, `--accent-wash`, `--scrim`, `--glow-scan`, the functional `--danger`/`--warn`/`--ok`, the `--font-*`, `--text-*`, radii, z-layers and durations: whatever the current `tokens.css` defines and `ui/src/**` still uses) onto a v2 semantic token, in that one file. After your change, every `var(--...)` referenced anywhere in `ui/src` must resolve to a defined token, and unconverted screens must still render. P10 deletes the file and every legacy name; you neither delete it nor extend its use into new code (all new primitives use semantic tokens directly).

### Cross-cutting rules

- Prefer a token over a value, always: if a number is needed twice it is a token, and if it is needed once it is still a token when it expresses rhythm, colour or state (`UI_REFERENCE` §2).
- No spinner-only screens and no layout shift on data arrival: skeletons reserve the final layout (`UI_REFERENCE` §4, §8).
- The header comments in `ui/src/styles/tokens.css` and `ui/src/styles/globals.css` still describe the v1 identity (warm graphite, dark-only, Windows-native fonts) and are superseded by `UI_REFERENCE` §1. Rewrite them to describe the picked direction, so no statement under `ui/src/styles` contradicts the spec after this phase.
- `prefers-reduced-motion` disables every motion the primitives ship, including any ambient drift the direction describes (`UI_REFERENCE` §7).
- No new npm dependency for fonts, icons or styling; the phase is a rewrite with the dependencies already in `ui/package.json` (`UI_REFERENCE` §1, 0.4.5 D15).
- The §8 performance budgets are not negotiable by a direction: initial JS ≤ 250 KB gzip, route-split, interaction latency < 100 ms.

## What you may not do

- **No route work beyond the dev-only Kitchen route.** No NavRail entry, no `/work`, `/work/:id`, `/insights`, `/ask` route, no Settings restructure, no change to `ui/src/app/**` beyond the single dev-gated Kitchen registration line.
- **No tone or copy changes.** `UI_REFERENCE` §9 copy stays exactly as written. Sample copy inside `/kitchen` is illustrative content for a palette decision, not a product copy edit.

## Acceptance

```
**Acceptance:** `/kitchen` renders every primitive in every state and theme; an automated
contrast check over the semantic pairs passes AA; lint rule (or a test) fails on raw hex, px
font sizes or non-token spacing in `ui/src/components/primitives`; existing screens still render
through the shim (screenshots attached to the PR); full verification suite green.
```

Decomposed into checkable items:

- [ ] `/kitchen` renders the picked direction on all five content samples (a real Settings page, a search result list, a session card, an answer with citations, a form showing every control state) **and** a gallery covering all 28 primitives named in deliverable 5.
- [ ] Every primitive appears in all its interaction states (default, hover, active, focus-visible, disabled, plus checked/selected/open/expanded/invalid/loading where it has them), and every data-bearing one shows all five view states from `UI_REFERENCE` §4.
- [ ] Every theme recorded in `UI_REFERENCE` §1 renders in `/kitchen` and is switchable there; the density token demonstrates `comfortable` and `compact` from one token family with `comfortable` as the default.
- [ ] The contrast test computes WCAG ratios over the semantic pairs (≥ 4.5:1 for body text, ≥ 3:1 for large text and UI boundaries) for every shipped theme, passes, and **fails** when one pair is deliberately broken (demonstrate the failure once in the build-loop notes, then restore the value).
- [ ] The token test fails on a raw hex, a px font size or a non-token spacing value inside `ui/src/components/primitives`, and reports zero hits on the committed tree. An allowlist that skips files is the same failure as a disabled rule.
- [ ] Unconverted screens still render through `tokens.compat.css`: every `var(--...)` used under `ui/src` resolves to a defined token, and screenshots of Recall, Timeline and Settings attached to the PR show no unstyled or transparent surfaces.
- [ ] Fonts are local files with licences beside them, present in `ui/dist` after `npm run build`, and no font or icon network URL (`url(http...)`, a font CDN) appears anywhere under `ui/src/styles`.
- [ ] `/kitchen` is dev-only: after a production build, `grep -rni kitchen ui/dist` finds nothing.
- [ ] Icons come from the one local set at one stroke width; `package.json` gained no icon or font dependency.
- [ ] Screenshots attached to the PR (Kitchen in every theme, plus the three unconverted screens) were captured from a dev run against synthetic seed data by the `docs/SCREENSHOTS.md` procedure, never from a live capture history.

## Verification, in order

One command per line, no `&&`. The UI block comes first because `cargo build` embeds `ui/dist`: a stale or broken build makes every later line meaningless. Run the whole list from the top after any fix.

```
cd ui
npm ci
npm run lint
npm run test
npm run build
cd ..
node scripts/stage-mcp.mjs
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo build --workspace
cargo test --workspace
grep -rnE '#[0-9a-fA-F]{3,8}\b|rgb\(|hsl\(' ui/src/components/primitives
grep -rn 'font-size: *[0-9]' ui/src/components/primitives
grep -rniE 'url\(http|fonts\.googleapis|fonts\.gstatic|cdn\.' ui/src/styles
grep -rni kitchen ui/dist
grep -rn 'data-theme' ui/src/styles/tokens.css
git diff --exit-code -- ui/src/bindings
```

Expected result per line, so a failure is unambiguous:

- `npm run test` runs the phase's own Node tests (`ui/test/*.test.mjs`): the contrast test and the token test. Both must pass.
- The two greps over `ui/src/components/primitives` return **zero** lines. A genuine need for a hairline or `1px` becomes a token, not an exception.
- The network-URL grep returns zero lines.
- The `ui/dist` grep returns zero lines (the route is dev-only and tree-shaken).
- The `data-theme` grep returns at least one line (themes are semantic swaps).
- `git diff --exit-code -- ui/src/bindings` is clean: this phase changes no Rust type. If it is not clean, something outside your ownership changed and you stop.

Paste the raw output of every line into `specs/05_BUILD_REVIEW.md`, and write the phase entry in `specs/08_CHANGELOG_AI.md` (`04` §7).

## Stop conditions

Halt the phase and ask, every time:

- **`UI_REFERENCE` §1 is still a placeholder**, or it names no theme count, or it describes a direction you cannot implement as written.
- **A product decision the specs do not answer.** For example a copy change, a new setting key, a new route, or a visual behaviour the §1 direction does not describe. Token values *inside* the picked direction (a radius number, a duration, one step of a scale) are your call; product decisions are not. Log the question in `specs/07_KNOWN_GAPS.md` with owner and date, then stop.
- **A spec contradiction.** Log it in `specs/06_PATCH_PLAN.md`, then stop.
- **A need to edit a file outside the owned paths.** Name the file and why; the expected ones (the router line, the two `ui/test/` enforcement files, and `ui/eslint.config.js` only if you take the lint route) still need the maintainer's yes before you write them.
- **A need to change the schema.** This phase touches no database; if a token or primitive seems to need a setting key, that is P3 or P7 territory. Log it in `specs/07_KNOWN_GAPS.md` and stop.
- **A verification command stays red after a genuine fix attempt.** Stop and paste the raw failing output; never weaken the command, the test or the rule.
- **The direction cannot meet §8 or §7**: it needs a third font family, a network fetch, an icon service, or it cannot reach AA in one of its themes. These contradict `UI_REFERENCE` §1/§8 and 0.4.5 D15; stop.
- **The Kitchen route cannot be kept out of the production bundle**, so a dev-only surface would ship. Stop.

## Do not

- Do not write stubs, placeholder components, empty components or "coming later" branches. A primitive that is not finished is not in the barrel.
- Do not hardcode expected values in tests to make them pass: the contrast test compares computed ratios against the WCAG thresholds, and the token test inspects the source, not a stored list of known-good strings.
- Do not weaken a lint rule, a test or the token fence to get green (no `eslint-disable` in the primitives, no allowlist over `ui/src/components/primitives`, no threshold lowered below AA).
- Do not touch `ui/src/components/icons.tsx`, `ui/src/routes/Settings.tsx`, `ui/src/components/domain/**`, `ui/src/components/shell/**`, `ui/src/overlay/**`, `ui/src/app/**` (one line excepted), `ui/src/bindings/**`, `crates/**` or `src-tauri/**`.
- Do not delete `tokens.compat.css` or any legacy token name: P10 does that.
- Do not commit to `main`, do not push, do not merge, and do not commit at all until the maintainer validates the content and names the target repo `nicolasestrem/screensearch` (0.4.5 D18).
